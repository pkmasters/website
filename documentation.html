Documentation

Welcome to the documentation page! Here you'll find detailed information about how I set up my website and the services I host.

Website Setup

I am using a Cloudflare domain from their registrar, which is a paid service per year. My website is hosted on GitHub Pages, where I created a pages repository and linked my domain to it. Additionally, I created a DNS record on Cloudflare to point to the GitHub Pages IP address. The website is built using simple HTML and CSS files.

Accessing Services with Twingate VPN

To access all of my services over the internet securely, I use Twingate VPN. This allows me to access local resources without exposing any ports.

Services For Public Access

For services that I host that integrate with the Internet, it all exposed using Cloudflare ZTNA.

With Zero Trust, I can "safely" expose my public services via a Cloudflare Tunnel. That way there is no exposed ports on my WAN IP, and users can access those services freely. For the most part, Cloudflare has been reliable, and downtime is very minimal and is usally on my side of infrastructure.

For added security, I implemented global WAF rules that are applicable across all of my publicly accessible web services. There are only 5 WAF rules and 1 custom rule set (zone) in the Free Tier. These are more than enough to secure my self hosted services.

This actually fixed an issue for me, which was geo blocking. My router doesn't have that function, and since I am not exposing my reverse proxy to the Internet, the WAF rules really helped in geo blocking requests that did not match the rule.

Hosting Services

I have a home server based on an HP Elitedesk 800 G4, running Proxmox VE. I have multiple VMs and LXCs running to service my needs; Network Management, DNS, Automation, Monitoring, App Testing, the like.

Services Hosted in Proxmox VE

  • Reverse Proxy: Caddy v2 as an internal reverse proxy, DNS01 challenge for wildcard certificate automation using ACME, internal HTTPS/SSL for all my internal applications.
  • Helpdesk: Zammad for ticket and incident management.
  • Automation: SemaphoreUI for all server relating automation. Patch management, VM creation, file pushes, the like. All integrated with Forgejo, local git platform.
  • Git Operations: Forgejo, hosting all local files needed for automation pipelines.
  • Internal SSO: Authentik, provides SSO via OIDC to all local applications. For applications that do not have native SSO, I use the proxy provider.
  • External SSO: Keycloak, configured for publicly accessible services that support SSO. User creation is done through SemaphoreUI.
  • Docker Management: Dockge, simple UI for stack management. From the same creator of Uptime Kuma. Hosts lots of staging services locally.
  • Monitoring Service: Uptime Kuma for monitoring locally available service uptime. Gatus for monitoring externally available service uptime
  • DNS: Technitium DNS in a 2x cluster managing all internal DNS records and advertising/malicious domains. Forwaded to an internal AD to retain internal domain access.
  • Password Management: Vaultwarden, works with official Bitwarden applications.
  • Remote Management: ControlR, remote control for all my servers.
  • Game Servers: Crafty, hosting a Minecraft server. (now migrated to my cloud server)

Crafty and Public Access Setup

For my Minecraft server (Crafty), I use standard DNS records and port forwarding to allow players to join my Minecraft Server.

This typically involves adding public DNS records that point to the server IP on the Minecraft server port. This is done through SRV records.
